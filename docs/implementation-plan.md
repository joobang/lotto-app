# 구현 계획과 착수 기준

## 단계 1 · 전 회차 데이터와 적재

- LOTTO-01·05. 1회부터 동행복권에서 확인한 최신 회차까지 초기 스냅샷을 확보한다. 회차 누락·중복, 추첨일, 본번호·보너스를 검증한 뒤 기존 백엔드의 분리된 로또 영역으로 적재한다.
- 초기 자료의 출처와 확인 범위를 기록한다. 동일 데이터를 다시 적재했을 때 건수와 값이 같고, 누락·충돌 입력에서 마지막 정상본이 유지돼야 한다.
- 첫 완료 조건은 초기 이력 연속성 검사, 최신·회차별 조회, 새 회차 1건 추가와 재시도 검증이다.

## 단계 2 · 분석과 전체 통계

- LOTTO-03·06. 번호별 카운트와 동시 출현, 본번호 일치 분포, 유사 회차, 역대 구성 집계를 구현한다.
- 가상의 회차를 사용해 수작업으로 기대값을 정한다. 전체 불일치, 6개 일치, 5개 일치와 보너스, 최신 회차 우선 동률, 정확히 일치한 횟수의 합을 검증한다.
- 45개 번호 빈도 순위의 공동 순위와 번호가 한 번도 안 나온 경우를 검사한다. 숫자 입력 순서를 바꿔도 분석 결과가 같아야 한다.

## 단계 3 · 뽑기 연출 시안과 iOS 화면

- 시각 작업은 [뽑기 화면과 연출](draw-experience.md)의 준비·번호 공개·결과 카드를 연결한 프로토타입부터 검토한다. 랜덤·통계가 공통으로 쓰는 진행 상태와 동작 줄이기까지 확인한 뒤 나머지 화면으로 확장한다.

- LOTTO-02·03·06. 내 번호 목록·오프라인 저장, 분석 네 페이지, 전체 역대 통계와 회차 상세를 구성한다.
- 저장·이름 수정·번호 수정·삭제·재실행 복원을 검사한다. 좌우 넘기기와 탭 모두로 분석 페이지를 이동하고, 선택 조합과 반영 회차가 계속 표시되는지 확인한다.
- 유사 회차 상세에서는 일치한 본번호와 보너스를 별도 라벨로 확인한다. 로딩, 빈 결과, 마지막 정상 데이터, 다시 시도 동작을 확인한다.

## 단계 4 · 독립 뽑기 기능과 실기기 검증

- LOTTO-04. 랜덤 뽑기와 역대 통계 뽑기를 각각 독립 메뉴로 연결한다. 생성 결과는 기존 저장·분석 흐름으로 연결한다.
- 랜덤·빈도·구성 각 모드에서 고정 번호 유지, 값 범위, 여섯 수 중복 금지, 한 응답 안의 조합 중복 방지, 기준 설명을 검사한다.
- 통계 모드의 가상 데이터에서 예상 가중치, 지원 가능한 구성, 고정 번호 제약과 생성 가능 수가 부족한 경우를 확인한다. 고정 번호 6개·중복 번호·허용하지 않은 생성 수는 입력 오류로 확인한다.
- 실제 iPhone에서 오프라인 랜덤 생성, 통계 갱신 실패 안내, 결과의 저장과 재실행 복원을 확인한다. 공유 백엔드에서 로또 실패와 기존 일정 API의 실패가 서로 전파되지 않는지도 확인한다.

## 첫 구현 작업

단계 1부터 착수한다. 검증된 초기 스냅샷을 정하고 적재 검사의 기대값을 먼저 정한다. 백엔드 연동과 운영 배포는 해당 작업의 확인 범위와 사용자 요청에 따라 진행한다.
