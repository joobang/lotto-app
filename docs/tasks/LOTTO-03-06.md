# LOTTO-03·06 · 이력 분석과 전체 통계

- 시작 기준 앱 `0080501`, 백엔드 `cc22e2f`. 각 레포의 작업 브랜치는 `codex/lotto-historical-analysis`다.
- 범위는 전체 번호 통계와 저장한 조합의 네 페이지에 필요한 분석 API다.
- 예상 실패 사례는 동률 순위와 유사 회차 순서 오류, 보너스의 본번호 집계 혼입, 0건·누락 회차 혼동, 한 응답의 집계 시점 불일치, 요청 번호의 불필요한 저장이다.
- 완료 조건은 가상 회차로 계산을 검증하고 실제 초기 이력으로 HTTP 응답 전체의 집계가 일치함을 확인하는 것이다.

## 구현과 검증

- 백엔드 구현 커밋 `7d07d2f3beaa65676c4215e137394a51a58fb120`. `GET /v1/lotto/stats`와 `POST /v1/lotto/analysis`를 연결했다. 분석은 한 번의 DB 조회에서 받은 회차 목록과 집계 범위를 사용한다.
- Node 24.22.3 `npm test` 392건 통과. 가상 회차에서 본번호와 보너스 분리, 공동 순위, 0회 출현, 유사 회차 동률, 결과 상한, 입력 거절을 확인했다.
- 고정 PostgreSQL 이미지를 사용한 일회용 DB에서 마이그레이션 9개와 실이력 1~1251회를 적용했다. 전체 45개 번호 통계와 분석 응답의 모든 집계 필드를 별도 Python 계산 결과와 대조했다. `3, 11, 19, 24, 32, 41`의 최대 일치는 4개, 완전 일치는 0회이며 가장 최근의 4개 일치 회차는 268회다.
- HTTP 200·400·503, 분석 응답 캐시 방지, 기존 회차 및 상태 확인 경로를 점검했다. 가상 1252회 적재가 동시에 진행될 때 응답 안의 일치 분포 합계와 반영 범위가 일관됐다.
- 운영 반영과 실기기 UI 검증은 후속이다. 디자인 구현은 연출 프로토타입부터 진행한다.
